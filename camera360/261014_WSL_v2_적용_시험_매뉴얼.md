## 6. C — 말단 → 엣지 → 서버 (`--forward`, 처음 해 보는 길)

노트북 DS 가 장비에서 받아 **자기 디스크에 저장하면서**, 받은 것을 서버 DS 의 같은 포트(`/push`)로 넘긴다. 서버 DS 는 장비에 붙지 않고 **넘겨 오는 것만** 받는다. 360 은 노트북(127.0.0.1)에만 보낸다 — 노트북이 서버로 넘긴다.

### 6-0. 먼저 확인할 것 — 「경로 문제」는 대부분 여기서 걸린다

| # | 확인 | 어떻게 |
|---|---|---|
| 1 | **서버 · 노트북 둘 다 v2 DS** 다 | 옛 서버는 새 노트북이 넘긴 상태(JSON 객체)를 못 읽고 버린다 — 서버 응답의 `bad` 가 늘고 서버 `states.jsonl` 이 빈다. 5-1 을 먼저 한다 |
| 2 | 서버 DS 는 **`--no-pull`** 로 띄운다 | 안 그러면 서버도 장비에서 직접 당겨, 같은 소스 폴더에 두 길이 섞인다 |
| 3 | 노트북(WSL)에서 서버 포트가 닿는다 | 아래 반복문이 쓰는 소스마다 `OK`. 테일넷 주소를 쓰면 **윈도우 Tailscale 이 붙어 있어야** WSL 에서도 닿는다(NAT 방식 WSL 은 윈도우를 거쳐 나간다) |
| 4 | `--forward` 에는 **주소만** 적는다 | 포트는 소스마다 같은 번호(10001 ~ 10004)를 쓴다. `http://` 나 포트를 붙여도 주소만 뽑아 쓰지만 헷갈리지 않게 주소만 |
| 5 | 360 은 노트북에만 보낸다 | 서버로도 따로 보내면 서버 cam360 폴더에 같은 장이 두 번 들어간다 |
| 6 | 같은 시험인지 시간으로 짝짓는다 | 실행 폴더 이름이 둘이 다르다 — 서버는 UTC, 노트북은 노트북 시각. 서버 기록의 `edge.frame_file` 이 **노트북 쪽 경로**다(노트북 `stream_data/<edge.frame_file>`) |

```bash
# 노트북 — 3번 확인
SERVER=<서버 주소>
for p in 10001 10002 10003; do timeout 3 bash -c "</dev/tcp/$SERVER/$p" && echo "$p OK" || echo "$p 안 됨"; done
```

### 6-3. 끝내기와 짝 맞추기

1. 360 · 비전을 끈 뒤 **노트북 보고 줄의 `대기` 가 0 이 될 때까지 기다렸다가** 노트북 DS 를 `Ctrl+C`. 끝 줄에 `넘김 N (못 넘기고 버림 N, 남은 대기 N)` 이 찍힌다 — 남은 대기는 서버로 못 간 것이다(노트북 디스크에는 있다).
2. 서버 DS `Ctrl+C`.
3. 짝 맞추기 — 둘 다 끈 뒤 노트북에서
   ```bash
   cd ~/physical_demo/data_stream && python3 v2_run_check.py stream_data | tee ~/v2_results_261014/C_edge_run_check.txt
   ```
   를 치고, 서버에서 6-2 의 서버 명령을 한 번 더 친다. 소스마다 노트북 `기록 N줄` 과 서버 `넘기기 edge 칸 N줄` 이 같으면 다 넘어간 것이다. 다르면 그만큼이 못 넘어간 장이다(노트북 끝 줄의 `버림` · `남은 대기` 는 상태까지 센 수라 그보다 클 수 있다).

넘기기 대기열은 소스마다 300건이다. 망이 끊겨 그보다 많이 밀리면 **오래된 것부터 버린다**(`버림` 이 는다). 노트북 저장에는 영향이 없다 — 하천에서 이 길을 쓰면 「노트북에는 다 있고 서버에는 일부」가 될 수 있다는 뜻이다.
