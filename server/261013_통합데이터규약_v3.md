## 1. 이 문서 쓰는 법

### 1-1. 사람이 볼 때

- **자기 파트만 보면 된다.** §5에서 자기 파트 절(예: §5-2 GO1)을 열고, 항목을 위에서부터 적용한다.
- **각 파트는 그 파트 담당이 고친다. 고치는 날은 파트마다 다르다.** 날짜가 달라도 깨지지 않게 하는 진행 방법(고침 → 확인 → 함께 시험 → 배포)과, 순서가 어긋나면 생기는 일은 §6-5에 있다. 고치기 전에 한 번 읽는다.
- 항목마다 틀이 같다.

| 칸 | 뜻 |
|---|---|
| **지금** | 지금 코드가 내보내는 모양 (실제 코드·실측 기록에서 옮겼다) |
| **바꾼 뒤** | 고친 뒤 나가야 하는 모양 |
| **왜** | 근거가 되는 결정 번호(D·P·V·N·R)와 한 줄 이유 |
| **어디** | 파일 이름과 **검색어**(그 파일에서 Ctrl+F로 바로 찾히는 글자). 파일이 없거나 이름이 불분명하면 "이 값을 만드는 자리"를 설명했다 |
| **어떻게** | 고칠 내용. 필요하면 코드 조각 |
| **같이** | 같은 날 함께 바꿔야 하는 다른 항목 (🔗 표시). 하나만 바꾸면 받는 쪽이 깨진다 |
| **확인** | 고친 뒤 제대로 됐는지 보는 방법 |

- 적용 순서와 같은 날 묶음은 §6에 있다. **받는 쪽을 먼저 "새 이름·옛 이름 둘 다 읽게" 고치고, 그다음 보내는 쪽을 바꾼다.** 이 순서를 지키면 같은 날 묶음이 거의 사라진다.
- 다 바꾼 뒤에는 §7의 점검 스크립트로 DS 기록을 한 번에 검사한다.

## 2. 규칙

### 2-1. 표기 규칙 R1~R12

| 번호 | 규칙 | 이유 |
|---|---|---|
| R1 | 이름은 소문자 + 밑줄(`snake_case`). HTTP 표준 헤더(`Content-Type` 등)와 v2가 정한 `Frame-Meta`만 예외 | 지금 JSON 본문의 거의 전부가 이 꼴이다 |
| R2 | **같은 뜻 = 이름 하나, 같은 이름 = 뜻 하나.** 받는 쪽이 "이 장비는 이 이름을 쓰니까" 하고 해석하지 않게 한다 | 후처리에서 장비마다 따로 해석해야 했던 원인이다 |
| R3 | 약어를 쓰지 않는다. `conf`→`confidence`, `cls`→`class_id`, `xyxy`→`bbox`, `ts`→`timestamp`, `seq`→`sequence_id`. `id`와 단위 꼬리(`_s`·`_ms`·`_m`·`_deg`·`_pct`)는 허용 | `ts` 한 이름이 세 가지 뜻으로 쓰였다 |
| R4 | 단위가 있는 숫자는 이름 끝에 단위를 붙인다. **새로 만들거나 이름을 바꾸는 칸에 적용한다.** 지금 있는 장비 본문 칸(`vx`, `yaw_rate` 등)은 이번에 이름을 바꾸지 않는다(D8) | 단위가 달라도 이름이 알려 주면 틀리게 읽지 않는다 |
| R5 | **시각은 ISO 8601, 밀리초 3자리, `+09:00` 고정** (D1). 예: `2026-10-12T14:10:31.086+09:00`. 예외: 명령 기한(protobuf `deadline_unix_ms`) | §4 D1 |
| R6 | 기간·나이는 시각이 아니다. 숫자 + 단위 꼬리로 적는다 (`infer_ms`, `age_s`) | — |
| R7 | 숫자·참거짓은 JSON 숫자·참거짓으로 보낸다. 글자로 바꾸지 않는다 | 360 `seq: "1"`, GO1 헤더 `"464"` |
| R8 | 모르면 `null`, 해당이 없으면 칸을 뺀다. `null`을 0으로 바꾸지 않는다 | HW·드론 계약과 같다 |
| R9 | 계산하면 나오는 값은 싣지 않는다. 예: `lag_ms` = `emitted_at − received_at`. 장비가 직접 잰 값(`infer_ms`, `age_s`)은 싣는다 | 같은 값이 두 이름으로 돌면 어긋난다 |
| R10 | `X-` 접두사를 쓰지 않는다 | RFC 6648 |
| R11 | `schema_version`은 형식(`숫자.숫자`)만 검사한다. 값이 달라도 거부하지 않는다. v2를 적용한 생산자는 `"2.0"`을 보낸다 (§4-2 N1) | BE 현행과 같다 |
| R12 | 같은 값을 두 자리에 싣지 않는다. **예외 하나: `frame_ref`.** `frame_ref`는 가리키는 프레임의 참조 복사본이라, 메시지 머리의 `timestamp`와 `frame_ref.timestamp`가 같은 값이어도 둘 다 싣는다 (D13). 이때 **두 값은 반드시 같아야 하고, 생산자는 같은 변수에서 둘을 쓴다** | GO1 state에 같은 값이 네 쌍 있었다 |

### 2-2. 시각 함수 — 생산자 공통

시각을 메시지에 적는 함수는 장비마다 하나만 둔다. 장비 안에서는 지금처럼 `now = time.time()`(epoch 초)으로 재고 계산한다. **메시지에 적는 순간에만** 이 함수로 바꾼다.

```python
from datetime import datetime, timedelta, timezone
import time

KST = timezone(timedelta(hours=9))

def iso_ms(t=None):
    """epoch 초(time.time() 값) → '2026-10-12T14:10:31.086+09:00'. 밀리초 아래는 버린다."""
    return datetime.fromtimestamp(time.time() if t is None else t, KST).isoformat(timespec="milliseconds")
```

받는 쪽에서 계산이 필요하면 읽을 때 한 번 숫자로 바꾼다.

```python
def to_epoch(v):
    """ISO 글자 또는 옛 epoch 숫자 → epoch 초(float). 모르면 None."""
    if isinstance(v, (int, float)):
        return float(v) / 1000.0 if v > 1e11 else float(v)     # 옛 기록의 epoch 밀리초도 받는다
    if isinstance(v, str):
        try:
            return datetime.fromisoformat(v).timestamp()
        except ValueError:
            try:
                return float(v)                                    # 옛 360 폼의 "1790918106.071032"
            except ValueError:
                return None
    return None
```

```javascript
// 브라우저·Node
const epochMs = Date.parse("2026-10-12T14:10:31.086+09:00");   // 1791781831086
```

이 함수를 쓰면 함께 사라지는 문제:

- **기기 시간대 표기.** 지금 HW `iso_now()`는 `astimezone()`을 쓴다. Pi 시간대가 UTC면 `+00:00`이 나간다(같은 순간이지만 글자 정렬·눈 비교가 어긋난다).
- **1 ms 어긋남.** 지금 GO1 `X-Timestamp`는 반올림, `X-Timestamp-Iso`는 버림이다.
- **AI 규격의 `Z` 표기.** AI `wire.py`는 UTC `…Z`로 적는다. 같은 순간이지만 표기가 하나가 아니다.

### 2-3. ID 값 규칙 (D6)

| 칸 | 값의 꼴 | 예 |
|---|---|---|
| `source_id` (장비) | `<기종>-<3자리>` | `go1-001` · `x500-001` · `wl-001` · `cam360-001` |
| `source_id` (프로그램) | 프로그램 이름 | `ds-vision` · `anchor360-live` · `drone-edge` |
| `camera_id` | `<장비 source_id>_<위치>` (VZ `vz-media-interface.md` §12와 같은 규칙) | `go1-001_front` · `x500-001_front` · `cam360-001_main` |
| `node_id` | 그 데이터를 만든 컴퓨터의 이름 (`/etc/node_id`, 없으면 hostname) | `pi7` · `pi3` · `sysai-server2` · 360 노트북 hostname |
| `zone_id` | 지금 값 그대로 (`zoneA`). 값 체계는 범위 밖(D8) | `zoneA` |

### 3-3. `frame_ref` — 프레임을 가리키는 방법 (D13 가)

```json
"frame_ref": {"camera_id": "x500-001_front", "sequence_id": 2246, "timestamp": "2026-10-12T10:00:00.125+09:00"}
```

- 세 칸은 **가리키는 프레임 헤더의 같은 이름 세 칸을 그대로 옮긴 것**이다. 이 밖의 칸은 넣지 않는다 (BE 규격 `additionalProperties: false` 유지).
- 세 칸이 모두 있어야 유일하다. `sequence_id`는 재기동하면 다시 시작하므로 `camera_id` + `sequence_id`만으로는 겹칠 수 있다.
- 쓰는 곳: 비전 결과, 드론 프레임 동기 state. 이 두 메시지는 머리의 `timestamp`도 같은 값이다 (R12 예외 — 두 값은 반드시 같다).
- 받는 쪽의 정합(F==F)은 세 칸이 모두 같을 때만 한다 (BE 콘솔·VZ 비전 탭의 지금 규칙과 같다).

### 3-5. 영상 프레임 헤더

영상 한 장에 붙는 JSON 한 덩어리다. 그릇(싣는 방법)은 경로마다 다르지만 **내용은 하나**다.

| 칸 | 뜻 | 필수 |
|---|---|---|
| 공통 머리 (§3-1) | `source_id` = 카메라가 달린 장비 | `schema_version`·`source_id`·`node_id`·`zone_id`·`timestamp`·`sequence_id`·`session_id` 필수 |
| `camera_id` | 카메라 (§2-3) | 필수 |
| `encoding` | `jpeg` · `h264` | 필수 |
| `width` · `height` | 이 그림의 해상도(px). 자른 경우 자른 뒤 크기 | 필수 |
| `keyframe` · `codec` | H.264일 때만. JPEG는 늘 키프레임이라 싣지 않는다 | H.264면 필수 |
| `sha1` | 그림 바이트 SHA-1 앞 16자. 번호가 달라도 같은 그림인지 가른다 | 선택 (GO1은 싣는다, P5) |
| `bytes` | 그림 크기. **그릇에 길이가 따로 있으면(HTTP `Content-Length`) 싣지 않는다** (P1) | 선택 |
| 장비 내부 칸 | 드론 `frame_id`·`input_crop`·`camera{}`·`flow`·`obstacles` (D11 — 이름·내용 그대로) + 새 내부 칸 `camera_index` (N2) | — |

**GO1 MJPEG (`Frame-Meta`, D7 가)**

```
--fr
Content-Type: image/jpeg
Content-Length: 13457
Frame-Meta: {"schema_version":"2.0","source_id":"go1-001","node_id":"pi7","zone_id":"zoneA","camera_id":"go1-001_front","sequence_id":1532,"session_id":"a1b2c3d4e5f6","timestamp":"2026-10-12T14:10:31.049+09:00","encoding":"jpeg","width":464,"height":400,"sha1":"cb83195c76df309d"}

<JPEG 바이트>
```

- `X-*` 15줄을 이 한 줄이 대신한다. 값이 JSON이라 숫자는 숫자로 간다 (R7).
- **ASCII만 쓴다** (`ensure_ascii=True`). DS가 파트 헤더를 latin-1로 읽는다.
- `sent_at`은 싣지 않는다 (D7-1). 그래서 JSON을 **장마다 한 번만** 만들어 모든 클라이언트에 같은 줄을 보낼 수 있다.

- `camera_index`는 드론 안에서 카메라 배열 칸으로 쓰는 정수다 (지금 `camera_id: 0`이 하던 일). 드론 밖에서는 `camera_id`를 쓴다 (D11 나, §4-2 N2).
- `frame_id`·`flow`·`obstacles`·`input_crop`·`camera{}`는 드론 안쪽 정렬·거리 계산에 쓰인다. 이름·내용 그대로 둔다 (D11).

```json
  "timestamp": "2026-10-12T15:02:11.420+09:00", "sequence_id": 17, "session_id": "…",
  "channel": "frame", "camera_id": "go1-001_front",
```

### 3-6. 비전 결과

**결과 머리**

| 칸 | 뜻 | 필수 |
|---|---|---|
| 공통 머리 | `source_id` = 결과를 만든 **프로그램**, `node_id` = 그 프로그램이 돈 컴퓨터, `timestamp` = 원본 프레임 시각 (D5) | 필수 (`sequence_id`·`session_id`는 선택) |

## 4. 결정 기록

### 4-1. 회신으로 정한 것 (D1~D13, P1~P5, V1~V7)

| 번호 | 결정 | 왜 (한 줄) |
|---|---|---|
| D1 | 시각은 **ISO 8601 · 밀리초 · `+09:00` 고정** | 성능·크기 차이는 무시할 수준이다(1건에 약 1 µs, 18 B). 기능 차이가 남는데, ISO는 초/밀리초 혼동이 구조적으로 생길 수 없고 사람이 바로 읽는다. 지금 데이터에서 실제로 문제를 일으킨 것이 단위 혼재였다 |
| D2 | 순번 이름은 `sequence_id` | BE·HW·드론·AI가 이미 이 이름이다 |
| D3 | `timestamp` = **데이터 시각** | 세 갈래가 같은 뜻의 시각이어야 카메라 셋·상태를 같은 순간으로 맞댈 수 있다. BE `message.schema.json`도 "지연 도착 데이터도 원래 측정 시각으로 정합한다"고 적었다 |
| D4 | GO1 영상 시각 = JPEG 생성 시각 (가). 약 37 ms 차이는 나중에 보정 | 한 장에 값이 하나라서 클라이언트마다 다르게 찍히는 문제가 없어진다 |
| D5 | 비전 결과 `timestamp` = 원본 프레임 시각 | "언제의 세상을 본 결과인가"로 상태·영상과 같은 축에 선다 |
| D5-1 | `emitted_at`은 둔다 | 결과의 늦음, 재생, 실시간/재처리 구분, 처리 시간 비교 |
| D6 | 제안한 ID 값을 칸에 넣는다 (§2-3) | 한 장비의 이름이 어느 경로에서나 같아야 한다 |
| D7 | GO1 프레임 헤더 = `Frame-Meta: {JSON}` 한 줄 (가) | 숫자가 숫자로 가고, DS 기록의 `sender`가 드론·360과 같은 모양이 된다. 브라우저 `<img>`는 영향이 없다 |
| D7-1 | GO1 프레임에 `sent_at`을 싣지 않는다 | JSON을 장마다 한 번만 만들 수 있다. 전체 지연은 `received_at − timestamp`로 본다 |
| D8 | 범위 밖 4가지 (단위 통일, 방위 기준, `zone_id` 값 체계, 명령 protobuf) | 이름 문제가 아니라 각자 정할 규약이다 |

| D10 | 칸 정리 — P1~P5로 나눠 정했다 (아래 P 행) | — |
| D11 | 드론 안쪽 고리(Pi ↔ 엣지)는 **경계만 통일** (나) | 판정은 드론 밖으로 나가지 않는다. 작동 중인 정렬 로직(`records.py`)을 건드리지 않는다 |
| D12 | 배터리 값 나이는 `battery.age_s`를 남긴다 (가) | 드론과 같은 이름이다 |
| D13 | `frame_ref`는 늘 3칸 `{camera_id, sequence_id, timestamp}` (가) | `frame_ref`만 떼어 봐도 프레임이 유일하게 정해지고, 모양이 하나다. 대가는 같은 값 1개(약 44 B)와 R12 예외 하나 |

### 5-1. BE (`Physical-Project-mk2/`)

#### BE-01 · 공통 머리 규격 — `timestamp`의 뜻, `sent_at`, 판 `2.0`

- **지금:** `contracts/common/message.schema.json`의 `timestamp` 설명이 "메시지 생성 시각"이다. `schema_version` 설명에 "현재 규격 버전은 '1.1'"이라고 적혀 있다.
- **바꾼 뒤:** `timestamp` = 데이터 시각. 선택 칸 `sent_at` 추가. 현재 판 `2.0`.
- **왜:** D3 · D1 · N1 · N11. 같은 파일 설명이 이미 "재전송된 지연 도착 데이터도 원래 측정 시각으로 정합한다"고 적고 있어서, 뜻을 그쪽으로 맞추는 것이다.
- **어디:** `contracts/common/message.schema.json` · 검색어 `"timestamp": {` · `"schema_version": {`
- **어떻게:**
  1. `timestamp.description` → "데이터 시각 — 그 데이터가 가리키는 순간(값을 잰 순간, 그림을 손에 넣은 순간). 메시지를 조립·발행한 순간이 아니다. 비전 결과는 원본 프레임 시각. RFC3339 · 밀리초 · `+09:00`(생산자 규칙)."
  2. `properties`에 추가: `"sent_at": {"type": "string", "format": "date-time", "description": "선택. 보낸 순간. 데이터 시각과 따로 봐야 할 때만 싣는다."}`
  3. `schema_version.description`의 현재 판을 `'2.0'`으로. 정규식은 그대로 둔다 (`1.x`를 보내는 생산자도 계속 통과).
  4. `required`는 바꾸지 않는다. `+09:00`은 생산자 규칙이고 검증기로 강제하지 않는다 (옛 생산자를 격리하지 않으려고).
- **같이:** BE-06(예제).
- **확인:** `pytest tests/test_payload_contract.py -q` 통과. `examples/envelope-valid.json`에 `sent_at`을 넣어도 통과해야 한다.

#### BE-02 · `frame_ref` 규격 — `{camera_id, sequence_id, timestamp}`

- **지금:** `frame-reference.schema.json`: 필수 `source_id`(카메라 키) · `capture_timestamp`("엣지가 프레임 경계를 확정한 시각") · `sequence_id`, 선택 `frame_id` · `time_sync_state`. `additionalProperties: false`.
- **바꾼 뒤:** 필수 `camera_id` · `sequence_id` · `timestamp` 셋만. `additionalProperties: false`는 유지.
- **왜:** D13(가) · R2(`source_id`가 장비/카메라 두 뜻으로 쓰였다) · P3(`time_sync_state`는 읽는 곳도 채우는 생산자도 없어 뜻이 없다) · `frame_id`는 쓰는 곳이 없다(드론 `frame_id`는 드론 안쪽 칸이다).
- **어디:** `contracts/common/frame-reference.schema.json` · 검색어 `"source_id"` · `"capture_timestamp"` · `"frame_id"` · `"time_sync_state"`
- **어떻게:**
  1. **먼저 지금 파일을 복사해 둔다** — `frame-reference.v1.schema.json`. 복사본의 `$id`는 끝을 `…/frame-reference.v1.schema.json`으로 바꾼다. 서버가 `contracts/common/` 아래 모든 `*.schema.json`을 `$id`로 레지스트리에 올리므로(`backend/ingest/envelope.py` `build_registry`) `$id`가 겹치면 안 된다. 이 복사본은 과도기에 옛 헤더를 받으려고 둔다 (BE-03 · BE-07). 단계 5에서 지운다.
  2. 원래 파일(`$id` 그대로): `required` → `["camera_id", "sequence_id", "timestamp"]`. `source_id` 칸 이름을 `camera_id`로, `capture_timestamp`를 `timestamp`로 바꾸고 설명을 §3-3으로 고친다. `frame_id`·`time_sync_state` 칸을 지운다. 파일 맨 위 `description`의 원칙 10 문장은 BE-10에서 같이 고친다.
  3. `object-reference.schema.json`과 `detections.schema.json`도 이 파일을 `$ref`한다. 둘 다 고치지 않아도 새 모양을 따라간다. `object-reference`는 지금 내보내는 곳이 없고 시험에서만 쓴다.
- **같이:** BE-03 · BE-07 · BE-11 · VZ-03 · AI-02 (🔗 묶음 A·L, §6).
- **확인:** `pytest tests/test_contract_media.py -q` (예제를 BE-06에서 같이 고친 뒤). 이 파일의 두 시험은 기대값이 옛 모양이라 같이 고친다 — `test_frame_reference_structure_unchanged_description_updated`(칸 다섯·필수 셋을 새 칸 셋으로)와 `test_registry_resolves_object_reference_like_media_header`(예시 `frame_ref`를 `{camera_id, sequence_id, timestamp}`로, 거부 예시는 `frame_ref/timestamp`의 `+0900`). `test_registry_has_every_schema_by_id`는 v1 복사본도 레지스트리에 있는지 함께 본다 — 고칠 필요 없다.

#### BE-03 · 미디어 헤더 규격 — 평평한 프레임 헤더

- **지금:** `media-header.schema.json` 필수 `frame_ref` · `encoding` · `keyframe` · `width` · `height`, 선택 `codec` · `correlation_id`.
- **바꾼 뒤:** §3-5의 프레임 헤더. 필수: 공통 머리 7칸(`schema_version` · `source_id` · `node_id` · `zone_id` · `timestamp` · `sequence_id` · `session_id`) + `camera_id` · `encoding` · `width` · `height`. `encoding`이 `h264`이면 `keyframe` · `codec` 필수. 선택: `sha1` · `bytes`. `correlation_id` 지움. `additionalProperties`는 지금처럼 열어 둔다.
- **왜:** 프레임이 자기 자신을 `frame_ref`로 감쌀 이유가 없다. 세 갈래가 같은 공통 머리로 시작해야 바로 맞댈 수 있다. `correlation_id`는 명령 사슬용이라 프레임에 쓸 일이 없다.
- **어디:** `contracts/common/media-header.schema.json` · 검색어 `"required"` · `"frame_ref"` · `"correlation_id"`
- **어떻게:**
  1. **먼저 지금 파일을 복사해 둔다** — `media-header.v1.schema.json`. 복사본에서 `$id` 끝을 `…/media-header.v1.schema.json`으로, `properties.frame_ref.$ref`를 `"frame-reference.v1.schema.json"`으로 바꾼다 (BE-02의 복사본을 가리키게). 이 복사본이 있어야 엣지(EDGEHW-01)가 아직 옛 헤더를 보내는 동안에도 서버가 받는다 — 그래서 묶음 A가 "같은 날 필수"가 아니다. 단계 5에서 지운다.
  2. 원래 파일(`$id` 그대로): `required` 교체. `properties`에 공통 머리 칸은 `message.schema.json`을 `$ref`하거나 같은 정의를 둔다. H.264 조건은 `"if": {"properties": {"encoding": {"const": "h264"}}}, "then": {"required": ["keyframe", "codec"]}`. 설명의 "헤더의 frame_ref.source_id 는 엣지 입구 쿼리의 source_id 와 같아야 한다"를 "헤더의 `camera_id`는 입구 쿼리의 `camera_id`와 같아야 한다"로.
  3. `$comment`의 "frame_ref 가 $ref 하는 frame-reference.schema.json 은 additionalProperties:false 라…" 문장은 v2 파일에서 지운다 (프레임 헤더에 `frame_ref`가 없어졌다).
- **같이:** BE-07 · BE-11 · EDGEHW-01 · VZ-02 (🔗 묶음 A).
- **확인:** `pytest tests/test_contract_media.py -q`.
  - 음성 예제 셋(`media-header-invalid-missing-encoding` · `-keyframe-type` · `-timestamp-offset`)은 새 모양으로 고쳐 계속 거부되는지 본다. `-timestamp-offset`은 이제 맨 위 `timestamp`의 `+0900`을 거부하는 예제가 된다.
  - `media-header-invalid-frame-ref-extra.json`은 v2에 `frame_ref`가 없으므로 v2 예제에서는 지운다.
  - 양성 예제 `media-header-valid-unknown-encoding.json`(모르는 `encoding`이 통과한다)은 새 모양으로 남긴다.
  - 지금의 `media-header-valid.json`은 `media-header-v1-valid.json`으로 이름을 바꿔 남기고, v1 검증기로 통과하는지 본다 (과도기 동안).
  - 시험 `test_media_header_required_set_and_no_enum`의 기대값(필수 다섯 · `frame_ref`의 `$ref`)을 새 필수 칸으로 고친다.

#### GO1-04 · GO1 영상 MJPEG 헤더 → `Frame-Meta` (`bench/go1_cam_view.py`)

- **지금:** `_mjpeg()` 핸들러가 **클라이언트마다·장마다** `X-*` 15줄을 만든다. `X-Timestamp`는 그 클라이언트에 보내는 순간, `X-Sha1`도 클라이언트마다 다시 계산한다. JPEG가 나온 시각은 재지 않는다.

- **바꾼 뒤:** `Frame-Meta: {JSON}` 한 줄(§3-5). JSON은 **JPEG가 나올 때 장마다 한 번** 만든다.

- **어디:** `bench/go1_cam_view.py` 검색어 `class MjpegWorker` · `self.jpeg, self.seq = buf[s:e + 2], self.seq + 1` · `def wait_frame` · `"X-Frame-Seq": seq`
- **어떻게:**
  ```python
  from common import schema
  try:
      ENTITY_ID = schema.Identity.resolve("robot").entity_id    # /etc/device_id (robot-node 와 같은 값)
  except Exception:

  def frame_meta(cid, seq, at, jpg):
      hub = HUBS[cid]
      meta = {
          "schema_version": schema.SCHEMA_VERSION, "source_id": ENTITY_ID,
          "node_id": NODE_ID, "zone_id": ZONE_ID,

          "timestamp": schema.iso_ms(at),                 # D4: JPEG 를 다 꺼낸 순간

          "sha1": hashlib.sha1(jpg).hexdigest()[:16],

      return json.dumps(meta, separators=(",", ":"), ensure_ascii=True)

  # MjpegWorker._collect — JPEG 하나를 꺼낼 때
  with self.cond:

      self.seq += 1
      self.jpeg = jpg
      self.meta_line = frame_meta(self.cam_id, self.seq, time.time(), jpg)
      self.cond.notify_all()

  # MjpegWorker.wait_frame → (seq, jpeg, meta_line) 를 돌려준다

  # _mjpeg 핸들러
  seq, jpg, meta_line = cam.wait_frame(seq)

  head = (b"--fr\r\nContent-Type: image/jpeg\r\nContent-Length: " + str(len(jpg)).encode()
  ```

#### GO1-07 · 수위계 · 액추에이터 state 시각

- **지금:** `envelope(self.identity, seq=self.seq)` — 조립 시각.

### 5-8. VZ (`viz-debugger/`)

같은 파일이 드론 브랜치 사본(`Physical-Project-mk2-Junho_drone/…/viz-debugger/`)에도 있다. 두 사본 모두 고친다. VZ는 **받는 쪽**이라 "새 이름을 먼저 읽고, 없으면 옛 이름"으로 먼저 올린다. 타입 검사는 `npm run typecheck`(화면 `tsconfig.json`과 목 게이트웨이 `gateway/tsconfig.json`을 둘 다 본다).

**VZ 안의 두 쪽을 구분한다.**

- **화면**(`src/`) — 실제 서버(BE)와 목 게이트웨이 양쪽에서 받는다. 단계 2에서 "둘 다 읽기"로 올린다.
- **목 게이트웨이**(`gateway/`) — BE와 이어지지 않은 VZ 자체 송신기다. 자기가 만든 봉투를 자기가 읽는다(구독 짝 맞추기 등). **단계 5에서 한 번에 새 이름으로 바꾼다 (V6).** 그때까지 옛 이름으로 보내고, 화면은 그것도 읽는다.

**입구에서 바꾸기 (V4).** 받은 것을 화면 모양으로 바꾸는 **입구 함수가 한 곳**이면, 새 모양은 그 입구에서 지금 내부 모양으로 옮겨 받는다. 그러면 안쪽 코드(정합 · 박스 환산 · 화면 그리기)는 손대지 않는다. 기존 시험은 그대로 통과해야 한다 — 다만 소스 글자를 찾는 정규식은 고치고, 새 모양 예시는 더한다(각 항목 「확인」). 미디어 헤더의 입구는 `src/media/parse.ts`(VZ-02), 비전 결과의 입구는 `src/tabs/data/vision.ts` `normalizeDetection`(VZ-03)이다. 봉투(VZ-01)는 읽는 곳이 다섯 파일에 흩어져 있어, 대신 두 이름을 다 읽는 작은 함수를 거치게 한다.

**검사 스크립트 주의.** `scripts/verify-*.mjs` 가운데 일부는 동작이 아니라 **소스 글자**를 정규식으로 찾는다. 읽는 코드를 함수로 바꾸면 동작은 맞는데 검사가 실패한다. 각 항목 「같이」에 적은 정규식을 같이 고친다.

### 6-1. 원칙

1. **받는 쪽을 먼저 "새 이름·옛 이름 둘 다 읽기"로 올린다.** (DS · VZ · AI 수신기 · 드론 엣지 · 우리 후처리 도구 · BE 입구)
2. 그다음 **보내는 쪽을 하나씩** 바꾼다. 하나 바꿀 때마다 DS 기록으로 확인한다(§7).
3. 모든 생산자가 `schema_version: "2.0"`을 보내는 것을 확인한 뒤에 받는 쪽의 옛 이름 읽기를 정리한다(급하지 않다 — 남겨 둬도 된다).
4. **각 파트는 그 파트 담당이 고치고, 고치는 날은 파트마다 다르다.** 이 순서는 날짜가 달라도 깨지지 않게 하려는 것이다. 진행 방법과 순서가 어긋났을 때 생기는 일은 §6-5에 있다.

이 순서를 지키면 "같은 날 바꿔야 하는 것"은 묶음 E(드론 신호 ↔ 드론 노드, 과도기 신호로 풀 수 있다) · F(360 업로드 ↔ 저장 폴더) · I(360 패킷 ↔ Unity) · J(DS 한 번 재기동) 넷만 남는다.

### 6-5. 파트마다 고치는 날이 다를 때 — 진행 방법과 여파

#### 6-5-1. 전제

- **각 파트는 그 파트 담당이 고친다.** BE · 우리 후처리 도구는 BE, GO1 · 센서 · HW 엣지는 HW, 드론 에이전트 · 드론 노드 · 드론 엣지는 드론, 360은 360, 데이터 스트림은 DS, 화면 · 목 게이트웨이는 VZ, 인지 프레임워크는 AI 담당이다.
- **고치는 날은 파트마다 다르다.** 모두 모여 같은 날 한꺼번에 바꾸지 않는다.
- 그래서 한동안 **v2 모양과 옛 모양이 섞여 돈다.** 이 문서의 순서(받는 쪽 먼저 · 둘 다 읽기 · 과도기 갈래)는 그 기간에 아무것도 끊기지 않게 하려는 것이다. 대신 아래 6-5-3의 일이 생긴다.

#### 6-5-2. 한 항목을 진행하는 방법 — 고침 → 확인 → 함께 시험 → 배포

| 순서 | 누가 | 할 일 | 현황표(§6-4) "상태" |
|---|---|---|---|
| 1 시작 전 | 담당 | 항목의 「같이」와 현황표의 "먼저 끝나야 하는 것"을 본다. 상대 항목이 아직 배포 전이면 **고치는 것은 해도 되지만 배포는 기다린다.** 고치기 직전에 「어디」 검색어로 자리를 다시 찾는다 — 그사이 다른 사람이 같은 파일을 고쳤을 수 있다 | — |
| 2 고침 | 담당 | 자기 파트 코드를 고친다. 장비 없이 되는 「확인」(시험 · 검사 스크립트 · 타입 검사)을 자기 환경에서 돌린다 | 고침 (날짜 · 이름) |
| 3 확인 요청 | 담당 → BE | 고친 항목 번호, 고친 파일, 돌린 확인과 그 결과를 BE(문서 관리자)에게 보낸다. 문서와 코드가 달랐던 곳이 있으면 같이 알린다(§1-3) | — |
| 4 확인 | BE | 항목대로 고쳤는지, 「같이」 상대가 준비됐는지 본다. 다르면 돌려보낸다 | 확인 (날짜) |
| 5 함께 시험 | 담당 + 받는 쪽 담당 | 실제 장비 · 서버로 §7-1을 돈다. 받는 쪽(DS · VZ · 엣지 · Unity · AI 수신기) 담당도 자기 기록 · 화면을 같이 본다 | — |
| 6 배포 | 담당 | 현장 장비 · 서버에 올린다. 「같이」 상대 담당에게 배포했다고 알린다. **받는 쪽은 "배포한 날"을 기준으로 움직인다** | 배포 (날짜) |

- 자기 파트 항목을 다 고친 뒤 한꺼번에 확인을 요청해도 된다. 다만 **배포는 §6-3 · §6-4의 순서를 지킨다.**
- 실측 · 시연 바로 앞에는 배포하지 않는다(6-5-3의 2 · 3).

#### 6-5-3. 섞여 도는 기간에 생기는 일

1. **기록이 섞인다.** 같은 DS 실행 폴더에 v2 장비와 옛 장비의 기록이 같이 남는다. 점검 스크립트(§7-2)는 아직 바꾸지 않은 장비를 위반으로 센다 — 정상이다. 장비(파일)별로 본다(§7-3).
2. **시각의 뜻이 장비마다 다르다.** 옛 장비의 `timestamp`는 메시지를 조립한 시각이고, v2 장비는 데이터 시각이다(D3). GO1 state는 최대 20 ms, 드론 state는 약 17 ms 차이가 난다(§4-3 · DRONE-04). 섞인 기간 기록으로 장비 사이 시간 차를 잴 때는 `schema_version`으로 갈라 해석하고, 결과에 장비별 판을 적는다. 한 장비를 바꾼 날의 앞뒤 기록을 그대로 이어 비교하지 않는다.
3. **실측 · 시연 날에는 판을 맞춘다 (권장).** 논문 · 분석에 쓸 기록을 남기는 날에는 그 실측에 쓰는 장비를 전부 같은 판(전부 옛 판, 또는 전부 v2)으로 맞춘다. 실측 전에 현황표로 확인하고, 실측 메모에 장비별 판을 적는다.
4. **과도기 코드가 오래 남는다.** 받는 쪽의 "둘 다 읽기", BE의 v1 헤더 갈래와 쿼리 `source_id`, 드론 과도기 신호의 옛 칸(DRONE-03 — 이것만은 DRONE-04 배포 뒤 드론 담당이 지운다), VZ 목 게이트웨이의 옛 이름은 단계 5까지 남는다. 마지막 생산자가 배포될 때까지 지우지 않는다. 하나라도 먼저 지우면 아직 옛 모양을 보내는 장비가 끊긴다.
5. **VZ 화면은 두 송신기를 동시에 상대한다.** 실제 서버(BE-08 뒤 새 이름)와 목 게이트웨이(단계 5까지 옛 이름, V6)다. 그래서 VZ-01의 읽기 함수는 단계 5 전까지 지우지 않는다.
6. **되돌리기.** 한 파트에 문제가 생기면 그 파트만 이전 판으로 되돌린다. 받는 쪽이 둘 다 읽으므로 다른 파트는 그대로 둔다. 같은 날 묶음(F · I · J, 과도기 신호 없이 진행한 E)은 묶음째 되돌린다. 되돌렸으면 현황표의 "배포"를 지우고 「같이」 상대에게 알린다. 단계 5에서 과도기 코드를 지운 뒤에는 이렇게 되돌릴 수 없다 — 단계 5를 서두르지 않는 이유다.
7. **문서와 코드가 어긋날 수 있다.** 각 담당이 자기 날짜에 고치는 사이 저장소가 바뀐다(예: VZ 기준 사본이 10-07에서 10-13으로 바뀌었다). 검색어가 안 찾아지거나 코드가 이미 바뀌어 있으면 멋대로 맞추지 말고 §1-3대로 알린다.

#### 6-5-4. 순서가 어긋나면 생기는 일

"먼저 배포돼 있어야 하는 것"보다 "나중" 항목이 먼저 배포됐을 때다. **오류 없이 깨지는 것**이 더 위험하다 — 아무도 모른 채 기록이 비거나 화면이 멈춘다.

| 묶음 | 먼저 배포돼 있어야 하는 것 | 어긋나면 | 드러나나 |
|---|---|---|---|
| A | BE-07 | EDGEHW-01이 먼저 나가면 서버가 새 헤더를 옛 규격으로 검사해 `stage=schema`로 거부하고, 쿼리 `camera_id`는 `source_id required`로 접속을 거부한다 → 엣지 영상이 끊긴다. VZ-02의 쿼리를 먼저 바꾸면 VZ 영상 접속이 거부된다 | 서버 로그 · 화면에 보인다 |

### 7-1. 장비 하나를 바꿀 때마다

§6-5-2의 "5 함께 시험"에서 이 표를 돈다.

| 볼 것 | 방법 | 기대 |
|---|---|---|
| 메시지 모양 | `mosquitto_sub -h <브로커> -t '<토픽>' -C 1 \| python3 -m json.tool` (상태) · `curl …`로 헤더 한 장 (영상) | §3 예시와 같은 칸 |
| 시각 | 위 출력의 `timestamp` | `YYYY-MM-DDTHH:MM:SS.mmm+09:00` |
| 판 | `schema_version` | `"2.0"` |
| 받는 쪽이 살아 있나 | DS `/health` · VZ 화면 · 엣지·Unity 화면 | 바꾸기 전과 같다 |
| 기록 | DS가 그 장비를 몇 분 받은 뒤 아래 점검 스크립트 | 그 장비 파일의 위반 0건 |

### 7-2. 점검 스크립트 `check_v2.py`

DS 실행 폴더(`<저장 위치>/<stream>/<run>/`)의 `frames.jsonl` · `states.jsonl` · `vision/*/results.jsonl`이 v2 모양인지 본다. 표준 라이브러리만 쓴다. 아래 내용을 `check_v2.py`로 저장한다.

```bash
python3 check_v2.py <저장 위치>/drone/20261012_100000          # 실행 폴더 하나
python3 check_v2.py <저장 위치>                                  # 아래 전부
python3 check_v2.py robot1_frames.jsonl --max 2000               # 파일 하나, 앞 2000줄만
```

- 끝 코드: 0 = 위반 없음, 1 = 위반 있음, 2 = 읽을 파일 없음.
- `[위반]`은 v2 규칙을 어긴 줄 수와 첫 예다. `[참고]`는 위반은 아니지만 볼 만한 것(순번 건너뜀 = 받는 쪽에서 빠진 장)이다.
- 10-02 기록(옛 모양)에 돌리면 위반이 많이 나온다 — 그것이 정상이다. **장비를 v2로 바꾼 뒤 새로 쌓인 실행 폴더**에 돌린다.
- 이 스크립트는 v2 예시 기록(위반 0건)과 10-02 실측 기록(옛 이름을 전부 잡는다)으로 시험했다.

```python
#!/usr/bin/env python3
"""통합데이터규약 v2 점검 — DS 기록(jsonl)이 v2 모양인지 본다. 표준 라이브러리만 쓴다.

쓰는 법
  python3 check_v2.py <실행 폴더 또는 jsonl 파일> [...]
    폴더를 주면 그 아래 frames.jsonl · states.jsonl · vision/*/results.jsonl 을 모두 본다.
    파일 이름에 frames / states / results 가 들어 있으면 그 종류로 읽는다.
  --max N   파일마다 앞에서 N줄만 본다 (기본 0 = 전부)

끝 코드  0 = 위반 없음, 1 = 위반 있음, 2 = 읽을 파일 없음
"""
import argparse
import collections
import json
import re
import sys
from pathlib import Path

ISO = re.compile(r"^\d{4}-\d\d-\d\dT\d\d:\d\d:\d\d\.\d{3}\+09:00$")
VER = re.compile(r"^[0-9]+\.[0-9]+$")
HEAD = ("schema_version", "source_id", "node_id", "zone_id", "timestamp")
# v2 에서 없어진 이름 (어디에 있어도 위반)
OLD_FRAME = {"ts", "seq", "frame_seq", "captured_at", "observed_at", "frame_wh",
             "capture_timestamp", "captured_at_unix"}
OLD_RESULT = {"xyxy", "conf", "cls", "name", "image_wh", "recv_ms", "done_ms", "lag_ms", "header",
              "frame_ts", "weight", "checkpoint", "bbox_xyxy", "box", "boxes", "bbox_space", "source"}
OLD_RECORD = {"host", "file", "source"}


class Report:
    def __init__(self, path):
        self.path, self.n = path, 0
        self.bad = collections.Counter()
        self.example = {}
        self.note = collections.Counter()

    def fail(self, key, line_no, detail=""):
        self.bad[key] += 1
        self.example.setdefault(key, "%d줄 %s" % (line_no, detail[:120]))

    def info(self, key):
        self.note[key] += 1

    def print(self):
        print("\n== %s (%d줄)" % (self.path, self.n))
        if not self.bad:
            print("   위반 없음")
        for k, c in self.bad.most_common():
            print("   [위반] %-46s %6d건   예: %s" % (k, c, self.example[k]))
        for k, c in self.note.most_common():
            print("   [참고] %-46s %6d건" % (k, c))


def check_head(rep, i, obj, where, need_seq):
    for k in HEAD:
        if k not in obj:
            rep.fail("%s: 공통 머리 %s 없음" % (where, k), i)
    v = obj.get("schema_version")
    if v is not None and not (isinstance(v, str) and VER.match(v)):
        rep.fail("%s: schema_version 형식" % where, i, repr(v))
    elif v is not None and not v.startswith("2."):
        rep.fail("%s: schema_version 이 2.x 가 아님" % where, i, repr(v))
    t = obj.get("timestamp")
    if t is not None and not (isinstance(t, str) and ISO.match(t)):
        rep.fail("%s: timestamp 형식 (ISO 밀리초 +09:00)" % where, i, repr(t))
    if need_seq and not isinstance(obj.get("sequence_id"), int):
        rep.fail("%s: sequence_id 가 정수가 아님/없음" % where, i, repr(obj.get("sequence_id")))
    if "sent_at" in obj and not ISO.match(str(obj["sent_at"])):
        rep.fail("%s: sent_at 형식" % where, i, repr(obj["sent_at"]))


def check_frame_ref(rep, i, obj, where):
    fr = obj.get("frame_ref")
    if fr is None:
        return
    if not isinstance(fr, dict) or set(fr) != {"camera_id", "sequence_id", "timestamp"}:
        rep.fail("%s: frame_ref 모양 (camera_id·sequence_id·timestamp 셋만)" % where, i, repr(fr))
        return
    if not ISO.match(str(fr["timestamp"])):
        rep.fail("%s: frame_ref.timestamp 형식" % where, i, repr(fr["timestamp"]))


def check_frames(path, limit):
    rep = Report(path)
    seqs = {}
    with open(path, encoding="utf-8") as f:
        for i, line in enumerate(f, 1):
            if limit and i > limit:
                break
            rep.n += 1
            try:
                rec = json.loads(line)
            except ValueError:
                rep.fail("JSON 아님", i)
                continue
            for k in OLD_RECORD & set(rec):
                rep.fail("기록: 옛 이름 %s" % k, i)
            for k in ("received_at", "received_by", "frame_file", "stream", "sender"):
                if k not in rec:
                    rep.fail("기록: %s 없음" % k, i)
            if "received_at" in rec and not ISO.match(str(rec["received_at"])):
                rep.fail("기록: received_at 형식", i, repr(rec["received_at"]))
            s = rec.get("sender") or {}
            if any(str(k).startswith("X-") for k in s):
                rep.fail("프레임: X-* 헤더가 남음 (Frame-Meta 미적용)", i)
            for k in OLD_FRAME & set(s):
                rep.fail("프레임: 옛 이름 %s" % k, i)
            if "_file" in s:
                rep.fail("프레임: DS 가 붙인 _file 이 남음 (P2)", i)
            check_head(rep, i, s, "프레임", need_seq=True)
            for k in ("camera_id", "encoding", "width", "height", "session_id"):
                if k not in s:
                    rep.fail("프레임: %s 없음" % k, i)
            for k in ("width", "height"):
                if k in s and not isinstance(s[k], int):
                    rep.fail("프레임: %s 가 정수가 아님" % k, i, repr(s[k]))
            if s.get("encoding") == "h264":
                for k in ("keyframe", "codec"):
                    if k not in s:
                        rep.fail("프레임(h264): %s 없음" % k, i)
            key = (s.get("camera_id"), s.get("session_id"))
            q = s.get("sequence_id")
            if isinstance(q, int):
                last = seqs.get(key)
                if last is not None:
                    if q <= last:
                        rep.info("순번 역전·중복 (같은 camera_id·session_id)")
                    elif q > last + 1:
                        rep.info("순번 건너뜀 (받는 쪽에서 빠진 장이 있음)")
                seqs[key] = q
    return rep


def check_states(path, limit):
    rep = Report(path)
    with open(path, encoding="utf-8") as f:
        for i, line in enumerate(f, 1):
            if limit and i > limit:
                break
            rep.n += 1
            try:
                rec = json.loads(line)
            except ValueError:
                rep.fail("JSON 아님", i)
                continue
            for k in OLD_RECORD & set(rec):
                rep.fail("기록: 옛 이름 %s" % k, i)
            for k in ("received_at", "received_by", "stream", "topic", "retain"):
                if k not in rec:
                    rep.fail("기록: %s 없음" % k, i)
            p = rec.get("payload")
            if isinstance(p, str):
                if rec.get("enc") == "json":
                    rep.fail("기록: enc=json 인데 payload 가 글자", i)
                try:
                    p = json.loads(p)
                    rep.fail("기록: JSON payload 를 글자로 저장 (객체로 저장해야 함)", i)
                except ValueError:
                    continue
            if not isinstance(p, dict):
                continue
            topic = str(rec.get("topic", ""))
            channel = topic.rsplit("/", 1)[-1]
            if channel not in ("state", "status", "heartbeat") or "/sim/" in topic:
                rep.info("세 채널 밖 토픽 (%s)" % channel)
                continue
            check_head(rep, i, p, channel, need_seq=channel in ("state", "heartbeat"))
            if "ts" in p:
                rep.fail("%s: 옛 칸 ts (frame_ref 로)" % channel, i)
            check_frame_ref(rep, i, p, channel)
            fr = p.get("frame_ref")
            if isinstance(fr, dict) and fr.get("timestamp") != p.get("timestamp"):
                rep.fail("%s: timestamp ≠ frame_ref.timestamp (D13 같은 값 규칙)" % channel, i)
            if p.get("reason") == "frame" and "frame_ref" not in p:
                rep.fail("%s: reason=frame 인데 frame_ref 없음" % channel, i)
            for path_ in (("battery", "pct"), ("velocity", "speed_mps"), ("pose", "yaw_deg"),
                          ("freshness", "bms_age_s"), ("freshness", "sampled_at")):
                d = p.get(path_[0])
                if isinstance(d, dict) and path_[1] in d:
                    rep.fail("%s: 지운 중복 칸 %s.%s" % (channel, path_[0], path_[1]), i)
            if "origin" in p:
                rep.fail("%s: origin 이 남음 (status 의 device_info 로)" % channel, i)
            fl = p.get("flight")
            if isinstance(fl, dict) and "system_status" in fl:
                rep.fail("%s: flight.system_status 가 남음 (P3)" % channel, i)
    return rep


def check_results(path, limit):
    rep = Report(path)
    with open(path, encoding="utf-8") as f:
        for i, line in enumerate(f, 1):
            if limit and i > limit:
                break
            rep.n += 1
            try:
                r = json.loads(line)
            except ValueError:
                rep.fail("JSON 아님", i)
                continue
            check_head(rep, i, r, "결과", need_seq=False)
            for k in OLD_RESULT & set(r):
                rep.fail("결과: 옛 이름 %s" % k, i)
            for k in ("frame_ref", "emitted_at", "width", "height", "detections", "model"):
                if k not in r:
                    rep.fail("결과: %s 없음" % k, i)
            check_frame_ref(rep, i, r, "결과")
            fr = r.get("frame_ref")
            if isinstance(fr, dict) and fr.get("timestamp") != r.get("timestamp"):
                rep.fail("결과: timestamp ≠ frame_ref.timestamp (D5·D13)", i)
            if "emitted_at" in r and not ISO.match(str(r["emitted_at"])):
                rep.fail("결과: emitted_at 형식", i, repr(r["emitted_at"]))
            for d in r.get("detections") or []:
                for k in OLD_RESULT & set(d):
                    rep.fail("검출: 옛 이름 %s" % k, i)
                b = d.get("bbox")
                if not (isinstance(b, list) and len(b) == 4):
                    rep.fail("검출: bbox [x1,y1,x2,y2] 아님", i, repr(b)[:60])
                elif not (b[0] <= b[2] and b[1] <= b[3]):
                    rep.fail("검출: bbox 순서 (x1<=x2, y1<=y2)", i, repr(b))
                if "label" not in d:
                    rep.fail("검출: label 없음", i)
    return rep


def find(paths):
    out = []
    for a in paths:
        p = Path(a)
        if p.is_dir():
            out += sorted(p.rglob("frames.jsonl")) + sorted(p.rglob("states.jsonl")) \
                + sorted(p.rglob("results.jsonl"))
        elif p.is_file():
            out.append(p)
    return out


def main():
    ap = argparse.ArgumentParser(description="통합데이터규약 v2 점검")
    ap.add_argument("paths", nargs="+")
    ap.add_argument("--max", type=int, default=0)
    a = ap.parse_args()
    files = find(a.paths)
    if not files:
        print("읽을 jsonl 이 없다")
        return 2
    bad = 0
    for p in files:
        name = p.name
        if "results" in name:
            rep = check_results(p, a.max)
        elif "states" in name:
            rep = check_states(p, a.max)
        elif "frames" in name:
            rep = check_frames(p, a.max)
        else:
            print("\n== %s — 종류를 모르겠다 (이름에 frames/states/results 가 없음)" % p)
            continue
        rep.print()
        bad += sum(rep.bad.values())
    print("\n합계 위반 %d건" % bad)
    return 1 if bad else 0


if __name__ == "__main__":
    sys.exit(main())
```

## 8. 옛 기록 호환

- **옛 기록(10-02 하천 실측 등)은 고치지 않는다.** 원본은 원본으로 둔다.
- 옛 기록을 읽는 도구는 §10 대응표대로 "새 이름 → 옛 이름" 순으로 찾는다. 시각은 §2-2 `to_epoch`로 숫자로 바꾼다(ISO · epoch 초 · epoch 밀리초 · 360의 초 글자를 다 받는다).
- 새 기록과 옛 기록은 `schema_version`으로 가른다: `2.x`면 v2, 없거나 `1.x`면 옛 모양.
- 옛 GO1 영상 기록은 `sender`가 HTTP 헤더 사전(`X-*`, 값이 글자)이다. 숫자로 바꿔 읽는다.
- 옛 GO1 영상 기록에는 JPEG 생성 시각이 없다. 옛 `X-Timestamp`(클라이언트에 보낸 순간)를 시각으로 쓰되, v2 기록과 약간(대개 수 ms ~ 수십 ms) 뜻이 다르다는 것을 결과에 적는다.
- 옛 DS 기록에는 받은 시각이 없다. Redis 항목 번호가 남아 있는 비전 결과(`recv_ms`)에서만 알 수 있다.
- 우리 후처리 도구(POST-01)가 이 규칙을 한곳에 모은다.
